# StoryMaker

给游戏策划用的**剧情对话编辑器**，用来替代原来的「Excel 填表 + 表格公式规整」流程。
编好的内容导出成一个 xlsx（三张表），直接交给 Unreal 导入。

使用者不是程序员，所以界面上一切都是中文、表格化、带校验和防呆。
**故意不做节点连线图**——那是开发者的直觉，对策划是灾难。

需求方是策划团队，改动以他们实际使用为准。

## 快速开始

### 策划：解压即用

把 `app-release/win-unpacked/` 整个文件夹拷给策划，双击里面的 `StoryMaker.exe` 即可，不需要安装：

1. 先「新建项目文件」或「打开已有项目文件」
2. 之后每次改动都会自动写回你选定的那个 `.json`（防抖 800ms）
3. 有新版本时软件会自己提示下载，重启后生效

项目内容**只有一份**，就在那个 `.json` 里，本机不缓存副本——换台电脑把 `.json` 拷过去就能接着编。

### 开发者

```bash
pnpm install
pnpm dev          # 开发服务器 http://localhost:5180
```

> 装依赖前先看下面的「注意」第 1 条。

## 常用命令

| 命令 | 产物 | 用途 |
|---|---|---|
| `pnpm dev` | 开发服务器 :5180 | 开发（`/api` 自动转给本地服务） |
| `pnpm build` | `dist/` 多文件 | 内网服务器 |
| `pnpm build:app` | `app-release/win-unpacked/` + `app-update/` | Electron 桌面版（唯一交付方式） |
| `pnpm test` | — | 675 个测试 |
| `pnpm verify:app-update` | — | Electron 自动更新自检（双源 / 清单 / 哈希） |

`pnpm build:app` 会同时生成 `app-update/`（`version.json` + `app.asar` + `changelog.json`）。桌面版设置页里能看
当前版本、手动检查更新；启动 3 秒后也会在后台查一次，有新版就提示下载，并按版本列出
「从当前版本到最新版本」的更新内容。更新只替换 `resources/app.asar`（约 1.5 MB），exe 不动，
所以这几个文件也要随版本提交。

更新内容写在根目录的 `CHANGELOG.md`：每个版本一节（`## 0.6.6` + 一行一条 `- 改动`），
打包时会转成 `app-update/changelog.json`；当前版本没写条目会直接打包失败。

单文件产物（`build:single`）已弃用，脚本已删除；`release/` 下只是历史产物，不再更新。

## 数据流

```
剧本（章节 > 段落 > 对话行 / 选项）
  → 对话表（无文本、无选项行；「角色显示名称」写角色表里那个名称的文本 key）
  → 选项表（含条件、跳转）
  → 角色表（角色ID / 播放位置 / 显示名称的文本 key / 表情差分列表 / 武器；
      武器每把一个字符串 `武器ID|分组导出名称|插槽导出名称|攻击模式导出名称`）
  → 特殊指令表（「其他 / 特殊」这类指令去重后一行一条：行名 / Command类 / 备注）
  → 图片表（一张立绘一行：行名 / 图片分类 / 备注 / 图片路径；
      路径由「图片分类」表里的存储路径 + 图片 ID 拼出来）
      表情图片（角色 × 表情差分）自动收集成 `PIC_<角色ID>-<表情标识>` 的行，
      路径是「角色立绘」分类路径 / <角色ID> / 图片ID；
      武器图标（每把武器一条 `PIC_武器ID`）路径是「武器图标」分类路径 / 图片ID
  → 音频表（一条音效一行：行名 / 音频 / 音效类型 / 备注；
      路径由「音效类型」表里的存储路径 + 音效 ID 拼出来）
  → 物品表（物品 ID / 物品名称 / 物品描述；
      名称与描述两列写 TXT_ItemName_<物品ID> / TXT_ItemInfo_<物品ID>）
  → 本地化表（TXT_ + ID 作 key，中英日）

本地化表末尾依次接上：UI 本地化的界面文案（TXT_Widget_* 这类）、
角色名与别名（TXT_<角色ID>_DefaultName / TXT_<角色ID>_OtherName-<别名序号>）、
物品名称与描述（TXT_ItemName_<物品ID> / TXT_ItemInfo_<物品ID>）、
武器分组 / 攻击模式 / 插槽的导出名称（TXT_WeaponTeam_* 等，中文就是它们的显示名称），
武器名与武器描述（TXT_WeaponName_<武器ID> / TXT_WeaponInfo_<武器ID>）

战斗（属性 / 事件 / 效果 / 技能 / 角色预设 / 武器）
  → GASGameplayTags（四张表里的条目自动收集，Tag 由名字合成）
  （GAS属性：行名=Tag / 属性标签 / 显示文本（TXT_Attribute_<属性名>）/ 属性类）
  → GAS属性 / GAS效果 / GAS技能 / GAS事件 / GAS角色 / GAS武器
  （GAS角色 的「武器」列：按顺序每条武器一个武器 ID；「武器绑定关系」列：每个装好的插槽一个
    `分组|插槽|武器下标|攻击模式`）
  （武器页顶部的攻击模式 / 插槽配置表各带「显示名称 + 导出名称」，
    GAS武器 的数值列是 弹匣容量 / 攻击速度 / 基础伤害 / 能量消耗 / 攻击范围，末尾依次是攻击模式 `(A,B)`、
    插槽 `("a","b")`、武器图标 `PIC_武器ID`、
    武器类 `前缀 + BP_Weapon_<武器ID去WEA_>`（拼不出来写 None））

导出 / Unreal导入设置（一行一张 DataTable：从编辑器里选表 + 选子表；
  数据表之后是五条竖排的前缀配置（GA类 / GE类 / 属性类 / 武器类 / Command类），
  前缀也是从编辑器的 Content 目录树里选文件夹拼出来的）
```

导出与界面上的「导出预览」用的是同一处 `buildAllSheets`，预览里看到的就是导出去的内容。
**「导入设置」不再是子表**：配置直接就是导入时用的那份数据，不用再导出一次。

## 导入到 Unreal（桌面版）

导出模块的「Unreal导入设置」页可以把导出内容**直接灌进打开着的 Unreal 编辑器**，
不用再手工拆 CSV、逐个点 reimport、拖图片。走的是引擎自带的 **Python Remote Execution**：

```
StoryMaker（Electron 主进程）
  ── UDP 239.0.0.1:6766 发现 ──→  编辑器（pong 带回项目名 / 引擎版本）
  ←─ TCP 回连 ──────────────────  编辑器
  ── command（一段 Python）───→  编辑器里跑
  ←─ command_result（逐条结果）──
```

前置条件（一次性）：

1. 工程开着，且 `.uproject` 里启用了 `PythonScriptPlugin`（BulletShootGame 已经启用）
2. 编辑器里 `Editor Preferences → Python → Enable Remote Execution` 勾上

然后在「设置」页配 **Unreal 项目文件**（`.uproject`）、**素材文件夹**，并决定要不要**自动连接**
（默认开，5 秒探一次）。这些全是本机配置，存在 localStorage，不进项目文件——换台机器路径本来就该不一样。
顶部工具条上的 **UE** 标签会显示连接状态：绿色=连上、灰色=没连，点一下跳到设置。

连上之后，「导出 → Unreal导入设置」里才能选数据表、配前缀。

**连上之后才能配数据表和前缀**：数据表从编辑器里检索出来的 DataTable 下拉里选，
前缀从 Content 目录树里选文件夹。没连上时只能看，不能改。

导入分两类：

- **素材（图片 / 音效）**：文件名（不含扩展名）= 图片 ID / 音效 ID 才认，大小写不同也算没对上。
  目标路径直接取导出表里那一列的完整引用，所以和策划看到的表永远一致。
- **数据表**：按「Unreal 导入设置」里配的那些行，把对应子表转成 CSV 写进临时目录，
  用 `DataTableFunctionLibrary.fill_data_table_from_csv_file` 灌进去。

配好之后用导出模块左侧工具列表里的 **「导出到 UE」**（在「Unreal导入设置」和「导出 Excel」中间）：
弹窗里是导入范围、`导入 / 全量导入` 两个按钮、实时进度条和逐条结果，导完点「完成」关掉。
没连上编辑器时这个按钮是灰的。

**素材跟条目 uid 绑定，不跟文件名绑定**：条目 ID 改名后，素材文件会跟着改名
（比如 `SCE_Black.png` → `SCE_New.png`），导入时也会把 UE 里的旧资产重命名，
不会变成「找不到素材」或者「旧资产残留」。表情立绘、武器图标同理。

**素材增量导入**：按「条目 uid + 路径 + 大小 + 修改时间」跟本机记录比，只导**新增、修改、改名**的；
没动过的跳过。界面上分别显示「新增 / 修改 / 改名 / 未变」，以及「已移除」——素材文件夹里删掉的文件
**不会去删 UE 里的资产**（可能被别的东西引用），只提示。
另有一个「全量导入」按钮，用于整个素材文件夹被覆盖、但文件大小和时间恰好没变的情况。
素材没有任何变更时「导入」照样能点——这时跳过素材、直接灌数据表（只改了表的时候就这么用）。

**顺序固定：先素材、后数据表。** 素材阶段只要有一个失败就停下，不导数据表——
数据表里存的是资源引用，素材没进去就灌表会让引用指向不存在的资产。

导入时有一条进度条，显示当前阶段（素材 / 数据表）、正在导的文件、第几项 / 共几项。

注意：脚本在编辑器主线程上同步跑，导入量大时**编辑器界面会卡住**，别关它。

## 素材管理（立绘 / 音效）

立绘（自定义图片、表情立绘、武器图标）和音效的每一行都有「素材管理」列，规则一句话：
**素材文件夹里的文件名（不含扩展名）就是图片 ID / 音效 ID**。

- 还没素材 → 「上传素材」按钮，选完自动复制进素材文件夹并按 ID 重命名（平铺在根目录）
- 图片有素材 → 「预览」弹窗看图、「…」换一张、「删除」
- 音效有素材 → 播放 / 暂停、可拖的进度条、当前时长 / 总时长，外加「…」和「删除」。
  **一次只播一个**：点第二条会把正在放的那条停掉。
- 同一个 ID 有多个文件（如 png + jpg）会提示重复，导入时用第一个

格式限制：图片 `png/jpg/jpeg/tga`，音效 `wav/ogg/flac`——都是 UE 能直接导进去的。
`tga` 浏览器显示不了，「预览」按钮会禁用，导入后在 UE 里看。

素材文件夹在「设置」页配；表情立绘和武器图标是自动收集的只读表，素材列同样能用。

指令 / 条件统一写成 `主指令|分支|参数名:值;参数名:值`（空分支留空段、无参数就空到底）：

```
剧情|演出|角色:CHA_西园寺雪;表情:悲伤
背包||物品:Item_Coin;运算符:=;数量:100
剧情|图片|
其他|特殊|特殊指令ID:SP_001
其他|延时|时长:0.5
```

键值用 `:` 而不是 `=`，是因为「运算符」这个参数的值本身可能就是 `=`；参数名与值里
不能出现 `|` `;` `:` `,` `"` `(` `)`。这条格式由字典（条件与指令模块）驱动：字典里给
每条指令定好「主指令 / 分支 / 参数列表」，填表时先选主指令、有分支再选分支，
然后按参数顺序从左到右出现下拉或输入框。

选项的「跳转目标」默认是**继续对话**（导出时下一对话ID = 选项所在那一行的 ID 尾号 +1，
如 `Dia_ch01_001-2` → `Dia_ch01_001-3`），也可以改成「对话结束」（这一格留空）
或跳到具体的某一句 / 某个段落的第一句。

导出的其它多值列写成 Unreal 数组字面量 `("a","b")`、键值对写成 `(("k","v"))`，
空列表写空单元格。战斗那边还和剧情一样：策划填的中间列（`类名`、带「（多选）」
「（换行分割）」后缀的）与 `Tag` / `DevComment` 不进导出表——`类名` 会补全成
`GA类` / `GE类` 全路径后单独成列。「特殊指令」表的 `Command类` 同理：
前缀在「Unreal导入设置」里改，拼成 `BP_Command_行名.…_C'`。

两条不能动的设计：

- **uid 与 readableId 分离**：所有引用都指向 `uid`——跳转目标、选项挂载、对话行的角色与显示名（选的是角色的某个别名）、战斗模块的属性 / 技能 / 事件引用、指令参数里指向各张表的值。`readableId`、角色 ID、名称文字只给人看、随时能改，所以改 ID、改名、拖拽排序后引用都不会断、本地化文本也不会串位；导出那一刻才按 uid 查回 ID / 名字，导出格式不变。
- **选项独立成表**：跳转目标存在选项上，对话行不带跳转；「选项的结果」已经下线，选完要执行指令就让选项跳到那个段落。

## 注意

1. **Electron 二进制要手动补下载**。`electron@44` 已移除 `postinstall`，`pnpm install` 不会下二进制，`pnpm build:app` 会报 "Electron failed to install correctly"。国内网络还需要镜像：

   ```powershell
   $env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
   node node_modules/electron/install.js
   ```

2. **改完前端跑 `pnpm test`**；改了打包或自动更新再跑 `pnpm verify:app-update`。

3. 单文件产物已弃用：`build:single` 脚本已删除，`release/` 下是历史文件，不要再重建或更新它。

更细的约定（踩过的坑、导出列结构、四个不要动的核心设计）见 [AGENTS.md](./AGENTS.md)。
